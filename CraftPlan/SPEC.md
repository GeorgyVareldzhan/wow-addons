# CraftPlan — как устроен аддон (версия 0.11.16)

Аддон для WoW 3.3.5a (сервер Sirus, русский клиент). Считает, что создать из имеющихся материалов, чтобы поднять профессии как можно выше, показывает это полосой вверху экрана, окном-картой «что из чего делается» и пошаговым планом.

Файлы: `CraftPlan.toc`, `CraftPlan.lua` (весь код и таблица порогов), `Bindings.xml` (назначение клавиш). Сохранённые данные: `CraftPlanDB` (на персонажа, SavedVariablesPerCharacter).

---

## 1. Откуда берутся данные

### 1.1 Рецепты (только из открытого окна профессии)
Игра отдаёт список рецептов, только пока открыто окно профессии. При событиях `TRADE_SKILL_SHOW` и `TRADE_SKILL_UPDATE` аддон:
- пропускает чужую профессию, открытую по ссылке (`IsTradeSkillLinked`);
- разворачивает все свёрнутые разделы окна (`ExpandTradeSkillSubClass`), чтобы увидеть все рецепты. Фильтры окна («есть материалы» и т.п.) не трогает;
- для каждого рецепта сохраняет: `name`, `kind` (цвет: `optimal` оранжевый, `medium` жёлтый, `easy` зелёный, `trivial` серый), `icon`, `link` (ссылка на изделие; для наложения чар это не предмет), `tools` (текст «нужно рядом: наковальня…»), `made` (сколько штук за раз — меньшее из разброса), `reagents` (список `{id, name, icon, count}`);
- если у рецепта идёт перезарядка (`GetTradeSkillCooldown`), ставит `cooldown = true` и `cdEnd` (время окончания). Пометка `cooldown` сохраняется и после окончания перезарядки (переносится из прошлого сканирования по имени);
- записывает профессию целиком: `profs[название] = { rank, max, recipes, scanned }`.

Профессия «Горное дело» попадает сюда через окно выплавки.

### 1.2 Уровень навыка (без окна)
При `SKILL_LINES_CHANGED` и при каждом пересчёте аддон читает `GetSkillLineInfo` и обновляет `rank`/`max` у известных профессий.

### 1.3 Пороги цвета рецептов (из файлов игры)
В конце `CraftPlan.lua` лежит таблица `CraftPlanThresholds`, извлечённая из архивов клиента Sirus (`SkillLineAbility.dbc` из `patch-ruRU-4.mpq`, русские названия из `Spell.dbc`):
`[номер навыка] = { ["название рецепта"] = { жёлтый_с, серый_с } }`. 4879 рецептов. Рецепты с одинаковым названием и разными порогами исключены (26 шт.) — для них цвет берётся из окна профессии.

Номера навыков (`SKILL_ID`): Кузнечное дело 164, Кожевничество 165, Алхимия 171, Кулинария 185, Горное дело 186, Портняжное дело 197, Инженерное дело 202, Наложение чар 333, Ювелирное дело 755, Начертание 773, Первая помощь 129.

Цвет при навыке `r` (`KindAt`), так считает сервер; сверено со всеми 62 рецептами персонажа:
- оранжевый — `r < жёлтый_с`;
- жёлтый — `r < floor((жёлтый_с + серый_с) / 2)`;
- зелёный — `r < серый_с`;
- серый — иначе.

`RecolorAll()` при каждом пересчёте переписывает `kind` всех запомненных рецептов по текущему навыку. Поэтому цвета верны и без открытия окна. Если у профессии все рецепты нашлись в таблице, пометка `stale` снимается.

### 1.4 Количество предметов
- Сумки: `GetItemCount(id или имя)` — всегда актуально.
- Банк: пока банк открыт (`BANKFRAME_OPENED`, `PLAYERBANKSLOTS_CHANGED`, `BAG_UPDATE` при открытом банке), аддон перечитывает основное хранилище и банковские сумки и сохраняет `bank[itemID] = количество` и `bankTime`. При закрытии банк не перечитывается (он уже недоступен и записался бы пустым).
- `TotalCount = сумки + банк`. Банк можно отключить галочкой «Учитывать банк» на вкладке «План» (`noBank`) — тогда считается только то, что в сумках. Текст количества: «12» или «12 (+30 в банке)».
- Почта не учитывается.

### 1.5 Торговцы
При `MERCHANT_SHOW` аддон запоминает товары, которые являются материалами известных рецептов и продаются без ограничения (`numAvailable == -1`): `vendor[itemID] = { price (за штуку, в меди), npc, zone }`.

### 1.6 Внешние аддоны (необязательны, проверяются перед использованием)
- **GatherMate** — где жилы руды (`GatherMate.zoneData`, `GatherMateMineDB`). Соответствие «руда → номера жил» задано в `ORE_NODES` (медь 201, олово 202, железо 203, серебро 204/209, золото 205/210, мифрил 206/207, истинное серебро 208/211, торий 212–215, тёмное железо 217, и т.д. до саронита 231/232).
- **Questie** — учителя профессий (по подписи NPC «Учитель кузнечного дела» и т.п., таблица `TRAINER_STEM`, только своей фракции) и торговцы предмета (`QueryItemSingle(id, "vendors")`).
- **Где добыть** (бывший аддон WhereToGet, теперь в конце `CraftPlan.lua`, в отдельной функции) — `WhereToGet_ShowItem(itemID)` ставит на карте мира метки источников предмета через Questie; кнопка у миникарты (перетащить предмет, щелчок, правый щелчок), `/wtg`. Привязок клавиш нет. Настройки — `WhereToGetDB` (на аккаунт), ореол — `CraftPlan/halo.tga`.

## 2. Расчёт плана (`BuildPlan`)

Один расчёт на всё: полоса, карта в режиме «Только план» и вкладка «План» показывают одно и то же.

### 2.1 Подготовка
- `producers[itemID] = { rec, prof }` — какой известный рецепт делает этот предмет (первый найденный). Так строятся цепочки «руда → слиток → изделие».
- **Отсечение невозможного**: материал «достижим», если он есть (`TotalCount > 0`) или его делает рецепт, все материалы которого достижимы (до 4 шагов в глубину, с защитой от кругов). Рецепты с недостижимыми материалами и рецепты на перезарядке в перебор не попадают.

### 2.2 Один проход (`Run(alpha, favored)`)
- Ведётся запас `have` (копия количеств), навык `rank[проф]` и остаток до потолка `left[проф] = max − rank`.
- `Simulate(rec, n)`: можно ли создать `rec` n раз. Берёт материал из запаса; чего не хватает — пытается сделать через `producers` (до 4 уровней, не сам рецепт, не рецепт на перезарядке), учитывая, что рецепт делает `made` штук за раз (лишнее остаётся в `extra` и идёт дальше). Возвращает: получилось ли, сколько чего уйдёт из запаса, промежуточные шаги, остатки.
- Цвет рецепта в ходе плана — `KindNow`: по порогам при текущем `rank` (если пороги известны), иначе сохранённый `kind`. Там же — сколько раз рецепт ещё останется оранжевым (`жёлтый_с − rank`).
- Вес цвета `GAIN`: оранжевый 1, жёлтый 0.5, зелёный 0.15, серый — не берётся. **Если «Брать жёлтые и зелёные» выключено (`allowChance`, по умолчанию выключено), берутся только оранжевые.**
- Каждый шаг выбирается лучший кандидат: `score = вес² / (доля запаса, которую съедает одно создание) ^ alpha`; у профессии `favored` счёт умножается на 1000. Рецепт с перезарядкой — не больше одного раза.
- Создаётся пачка: до `BATCH = 5`, у оранжевого — не дальше порога пожелтения и не больше `left`, у рецепта с перезарядкой — 1. Пачка уменьшается, пока `Simulate` не скажет «хватает».
- После выбора: материалы списываются, остатки промежуточного возвращаются в запас; промежуточные шаги и само изделие записываются в план (`AddEntry`).
- `AddEntry` считает для пачки: `sure` — сколько созданий точно дадут +1 (оранжевые, до порога и потолка), `maybe` — остальные, если рецепт после этого не серый (навык с шансом). Навык в плане растёт только на `sure`. У записи плана: `count` (сколько создать), `gain` (= сумма `sure`, точный прирост), `chance` (сколько созданий с шансом), `rankFrom`/`rankTo`, `step` (промежуточный шаг) и `forNames` (для чего он), `prereq` (что создать перед этим изделием и сколько).
- До 300 шагов, пока есть кандидаты.

### 2.3 Выбор лучшего прохода
Проходы: `alpha` = 1, 0.5, 2 и по одному проходу с приоритетом каждой профессии. Берётся проход с наибольшим суммарным точным приростом; при равенстве — где меньше созданий «с шансом». Итоговый список сортируется: сначала промежуточные шаги, затем остальное в порядке выбора.

### 2.4 «Дальше» (`cont`)
По каждой профессии, при навыке и запасе **после** плана:
- если `left = 0` — «нужен учитель» (`trainer`);
- иначе выбирается рецепт нужного цвета (оранжевые; жёлтые — только если разрешены) с наименьшей «ценой недостающего» (купить у торговца — в 10 раз дешевле, чем добыть). Количество: оранжевый — ровно до пожелтения (не больше `left`), жёлтый или без порогов — `NEED_CRAFTS = 10`;
- считается, чего не хватит (`missing`: материал → сколько), и какие промежуточные шаги нужны (`steps`); промежуточное раскладывается до сырья, если материал не продаётся у торговца;
- если подходящих рецептов нет — `noRecipes` («выучите новые у учителя»).

### 2.5 Когда пересчитывается
Через `REFRESH_DELAY = 1` секунду после: входа в игру, изменения сумок, открытия/изменения окна профессии, изменения навыков, конца боя, открытия банка. В бою не считается (полоса прячется). План считается и при скрытой полосе — он нужен карте.

Расчёт идёт в coroutine по кусочкам: не дольше ~8 мс за кадр (`SLICE_MS`, `Breathe()` в циклах), поэтому клиент не замирает даже на больших профессиях. Если данные изменились во время расчёта, он не обрывается, а после окончания запускается ещё раз. По окончании применяется результат (`ApplyPlan`): полоса, сводка, затем карта и вкладка «План» (`AfterPlan`).

Окно профессии: при открытии (`TRADE_SKILL_SHOW`) — разворачиваются разделы и читаются все рецепты; при обновлениях (`TRADE_SKILL_UPDATE`, их много) — рецепты перечитываются отложенно, вместе с пересчётом, без разворачивания разделов.

Ускорения: рецепты с недостижимыми материалами отсекаются; профессии на максимуме навыка в переборе не участвуют; проходы «с приоритетом профессии» — только если растущих профессий больше одной; «можно создать» на схеме и на полосе запоминается на одну перерисовку/пересчёт. Схема больше 500 предметов не рисуется — просит сузить фильтры.

Индикатор расчёта: пока план считается, под полосой «CraftPlan: считаю план… 45%» (точки бегут, процент — по числу пройденных стратегий), в заголовке карты «(считаю план… 45%)», на вкладке «План» — строка о том, что список обновится по окончании.

Результат хранится в `CraftPlan.fullPlan` (весь план), `CraftPlan.cont` (дальше), `CraftPlan.planCount` (рецепт → сколько создать), `CraftPlan.profSummary` (строка для кнопок профессий).

## 3. Полоса вверху экрана

- Без фона. Иконки 32×32 с промежутком 6, не больше `MAX_ICONS = 14`; если больше — справа «+N».
- Первая иконка — **значок карты** (голубая рамка, картинка карты): открывает/закрывает окно карты.
- Дальше — записи плана, которые дают навык: `gain > 0`, или `chance > 0` при разрешённых «с шансом». Промежуточные шаги без точного прироста на полосе не показываются (они в подсказке изделия).
- Рамка иконки — цвет рецепта. Внизу иконки «19/1»: серым — сколько раз можно создать из имеющегося (сумки и банк, с промежуточным до 4 шагов, без дележа материала с другими рецептами); после черты — что даст навык по плану: зелёным — точный прирост, жёлтым — сколько раз создать «с шансом» (если точного прироста нет).
- Подсказка иконки: изделие; «Сначала создайте это: нужно для …» (для промежуточного); «Можно создать из имеющегося: N раз»; «По плану создать: N раз»; «Навык: +N точно»; «Ещё N раз — навык с шансом»; строка порогов («Оранжевый ещё 22 раз (навык сейчас 88, жёлтым станет с 110). Пороги: жёлтый с 110, зелёный с 130, серый с 150»); материалы «есть / нужно на весь план»; напоминание забрать из банка (если в сумках не хватает, а в банке есть); «Сначала создайте из того, что есть: Медный слиток x20 — Горное дело»; «Нужно рядом: …».
- Щелчок — открыть карту на вкладке «Схема» с выбранной цепочкой этого изделия. Правый щелчок при открытом окне нужной профессии — выбрать рецепт и подставить количество (`TradeSkillFrame_SetSelection`, `TradeSkillInputBox`). Создаёт игрок сам.
- Shift + перетаскивание любой иконки — передвинуть полосу; место хранится в `barPos`.
- Свёрнутая полоса (`collapsed`) — остаётся только значок карты и стрелка `CraftPlanCollapse` (справа от значков; щелчок — свернуть/развернуть); кнопка «Просеять» тоже скрывается. Пока свёрнуто и закрыты карта крафта и торговец, `Refresh` план не считает (`CraftPlan.planStale = true`); посчитает при открытии карты (`OnShow`), торговца (`MERCHANT_SHOW`) или при разворачивании.
- Скрыта (`hidden`) — полоса не показывается, план считается.

## 4. Окно карты крафта

Рамка-диалог, по умолчанию 980×620 по центру. Перетаскивается за любое место, растягивается за уголок справа внизу (минимум 760×420), не уходит за экран. Размер и место хранятся в `mapSize`/`mapPos` и восстанавливаются при первом открытии. Закрывается крестиком и Esc.

Вверху слева — вкладки **«Схема | План»** (выбранная подсвечена, хранится в `mapTab`).

### 4.1 Вкладка «Схема»

**Верхние ряды:**
- Кнопки профессий: «Кузнечное дело 88/150 +22» (зелёное «+N» — точный прирост по плану, жёлтое «+шанс», оранжевое «(учитель)», серое «нечего»). Включена — золотой текст и подсветка; выключена — серый текст, бледная. Щелчок включает/выключает профессию на схеме (`map.off`). Подсказка: общие ингредиенты нескольких профессий. Кнопки переносятся на новую строку, если не влезают.
- Список «какие рецепты» (`map.kindMode`): «Всё, что даёт навык» (по умолчанию: оранжевые, жёлтые, зелёные), «Только оранжевые», «Оранжевые и жёлтые», «Только жёлтые», «Только зелёные», «Все рецепты (и серые)».
- Радиокнопки источника: «Из любых материалов» / «Только то, что можно создать» / «Только план».
- В режиме «Только план» кнопки профессий и список цветов скрыты (не влияют), радиокнопки встают в первый ряд.
- Справа вверху — поиск с крестиком очистки.

**Что попадает на схему:**
- «Из любых материалов» — рецепты включённых профессий выбранных цветов.
- «Только то, что можно создать» — из них только те, на которые хватает **всех** материалов (с учётом промежуточного до 4 шагов).
- «Только план» — ровно записи плана (`planCount`), без учёта профессий и цветов.
- Плюс вся цепочка к показанным: любой рецепт (любого цвета, даже из выключенной профессии), чьё изделие нужно показанному, — рекурсивно.

**Раскладка:**
- Колонка = глубина: сырьё — 0, изделие — 1 + самая глубокая часть. Конечные изделия (больше ни во что не идут) — всегда в последней колонке. Круговые рецепты обрываются.
- Первая колонка: сначала материалы, нужные нескольким профессиям, потом по профессии и названию. Остальные колонки — по средней высоте материалов (меньше пересечений).
- Колонки короче самой длинной растягиваются на всю высоту; одиночный предмет — посередине.
- Шаг колонок `COL_W = 174` (значок 30 + подпись 100 + промежуток 40), перед последней колонкой ещё `LAST_GAP = 50`. Строка 40.

**Значок предмета:**
- Рамка: цвет рецепта (у изделий), золотая — материал нескольких профессий, серая — обычный материал.
- Цифра в углу: в режиме «Только план» — как на полосе «19/1» (серым — сколько есть и можно создать, после черты — что даст навык по плану: зелёным точно, жёлтым — с шансом); иначе белая — сколько есть (сумки + банк), зелёная «+N» — нет, но столько можно создать из имеющегося (оценка по каждому предмету отдельно, без дележа запаса).
- Синяя сумка в левом нижнем углу — часть этого предмета лежит в банке.
- Значок в правом верхнем углу — рецепту нужно что-то рядом или в сумке (`tools`), по тексту требования (`TOOL_ICONS`): очаг/огонь/костёр — пламя (`Spell_Fire_Fire`), горн — печь с огнём (`Achievement_Cooking_MasteroftheOven`), наковальня — `Trade_BlackSmithing`, набор ювелира — камень (`INV_Misc_Gem_02`), прочее — гаечный ключ (`Trade_Engineering`). Инструменты-предметы (`TOOL_ITEMS`, сейчас набор ювелира 20815): если предмет есть в сумках (`GetItemCount`), значок и подпись не показываются. Подпись (`ToolText`) в подсказке и в плане: «Необходимо: Набор ювелира (нет в сумках)» или «Необходимо рядом: наковальня».
- Монета в левом верхнем углу — продаётся у торговца (виденного самим аддоном или по базе Questie; для руды база Questie не используется).
- Серый значок: материала нет; изделие, на которое не хватает материалов (и не сделать из имеющегося), — серое, полупрозрачное, подпись серая.

**Линии:** от правого края подписи материала к изделию, с изломом под прямым углом перед колонкой изделия, со стрелкой. Цвет — у каждого изделия свой (12 цветов по кругу), вертикальные участки разведены (у последней колонки шире).

**Подсказка значка:** предмет; «Есть: …»; «Продаётся: …»; «Нет, но можно создать: N шт.»; для изделия — «На сколько созданий хватает»: по каждому ингредиенту «есть X +Y можно сделать → на N», самый дефицитный помечен «ограничивает»; «Не хватает: … (есть X из Y)» (красным); «Создаёт: профессия (цвет)» и строка порогов; материалы «есть / нужно»; «Нужен для: …».

**Подсветка:** наведение — золотом вся цепочка материалов до сырья, голубым — всё, что из предмета делается; остальное тускнеет. Щелчок закрепляет подсветку (название вписывается в поиск; схема при этом не прокручивается) и, если открыто окно нужной профессии, выбирает рецепт. Правый щелчок — «где взять» (см. 6). Shift+щелчок — ссылка в чат. Поиск подсвечивает цепочки всех совпадений (без учёта регистра, в том числе русских букв) и прокручивает к первому, если его не видно. Крестик в поле поиска снимает выбор и поиск.

**Прокрутка:** колесо — вверх/вниз, Shift+колесо — влево/вправо, Ctrl+колесо — масштаб 0.4–1.5.

**Легенда** внизу — одна-две строки о рамках, цифрах и щелчках.

### 4.2 Вкладка «План»
Всё от «Схемы» скрыто. Вверху галочки «Брать жёлтые и зелёные рецепты (навык с шансом, тратит материалы)» (`allowChance`) и «Учитывать банк» (`noBank` — выключено) — при переключении план пересчитывается. Ниже — список с прокруткой:

1. **«Сейчас — из того, что есть»** — записи плана по порядку (если в сумках не хватает материала на весь шаг, а в банке есть — пометка «[забрать из банка]»; если рецепту нужно что-то рядом — «[нужно: …]»): «1. Выплавка меди — 20 раз  (Горное дело)», «2. Рунический медный пояс — 22 раз  навык +22 точно  Кузнечное дело: навык с 88 до 110». Щелчок — выбрать рецепт и количество в открытом окне профессии. Если ничего — «Из имеющихся материалов сейчас нечего создать для навыка».
2. **«Дальше — когда это кончится»** — по каждой профессии (навык после плана):
   - «Навык на максимуме. Идите к учителю» (щелчок — учителя на карте);
   - «Нет оранжевых рецептов. Выучите новые у учителя» (+ совет разрешить «с шансом»);
   - иначе нумерованные шаги: «Добыть/Купить: материал — N   жилы: зона1, зона2 / купить у торговца имя / где взять — щёлкните» → «Создать: промежуточное — N раз (профессия)» → «Создать: рецепт — N раз   навык +N точно / навык с шансом». Если всего хватает — «Всё есть — можно создавать».
3. **«Нужно сразу нескольким профессиям — всего»** — общие недостающие материалы.
4. Строка «Банк учтён по состоянию на дд.мм чч:мм» или «Банк ещё не открывали».

Строки с иконкой предмета, подсвечиваются под курсором, в подсказке — сам предмет.

---

### Итог плана (вкладка «План», после раздела «Сейчас»)
- «Итог, если сделать всё из того, что есть»: по каждой профессии из `fullPlan` — «Профессия: навык» (при точном приросте — «навык до навык+gain»), затем сумма `gain`, «+N точно» оранжевым и «+N с шансом» цветом рецепта — жёлтым или зелёным (сумма `chance` по `rec.kind`, только при `allowChance`); профессии без прироста не показываются.

## 5. Команды и клавиши
- `/cplan` — скрыть/показать полосу.
- `/cplan min` — свернуть/развернуть полосу.
- `/cplan map` — открыть/закрыть карту.
- `/cplan need` — переключить окно карты между вкладками «План» и «Схема» (открывает карту).

- `/cplan reset` — забыть все рецепты.
- «Назначение клавиш» → «CraftPlan (профессии)»: «Открыть/закрыть карту крафта», «Свернуть/развернуть полосу».

## 6. «Где взять» (правый щелчок по предмету, щелчок по материалу в плане)
1. Если аддон видел торговца — в чат: «продаётся у торговца имя (зона) за цену за штуку».
2. Если это руда — в чат зоны с жилами по GatherMate (до 6, по убыванию, текущая зона зелёным); жилы видны на карте и миникарте.
3. Иначе — `WhereToGet_ShowItem`: метки Questie на карте мира (мобы, объекты, торговцы); повторный вызов убирает метки.

## 6а. Подсказка к предмету «CraftPlan — пригодится»
- `AddUsesToTooltip` на `OnTooltipSetItem` у `GameTooltip` и `ItemRefTooltip`: для любого предмета (добыча с моба, сумки, ссылки в чате) выводит рецепты профессий персонажа, где он — материал.
- Источник — таблица `CraftPlanReagents` в конце `CraftPlan.lua`: `[itemID] = { навык, "рецепт", ... }`, 1034 предмета / 12580 связей, извлечено из `Spell.dbc` (реагенты, колонки 52–59/60–67, название — колонка 144) и `SkillLineAbility.dbc` (навык рецепта, только рецепты с серым порогом > 0) из `Data/ruRU/patch-ruRU-4.mpq`.
- Профессии и навык — из `GetSkillLineInfo`. Изученный рецепт (есть в отсканированном `profs[проф].recipes`) — цветом по текущему навыку (`KindAt`, иначе `rec.kind`); не изученный — красным с «не изучен, оранж. до Y», только если навык ещё ниже серого порога. Если окно профессии не открывали — цвет по навыку и пометка «откройте окно профессии».
- Порядок: оранжевые, жёлтые, зелёные, серые, затем красные (по жёлтому порогу); не больше 6 на профессию, дальше «и ещё N».

## 6б. Рыбалка (раздел в конце кода, обёрнут в `(function() … end)()` — свои локальные)
- Данные — `CraftPlanDB.fish`: `catch[itemID][зона]=штук` (по `LOOT_OPENED` + `IsFishingLoot()`), `zones[зона]={catches,escapes,minSkill}` (срыв — `UI_ERROR_MESSAGE` == `ERR_FISH_ESCAPED`), `mainHand/offHand` (оружие до удочки), `savedSound` (громкости до «громкого всплеска»), `loud`, `pinned`, `pos`.
- `CraftPlan.FishWhere(itemID)` → `true, "зоны"` для предметов из журнала (3 зоны с наибольшим уловом) или `POOL_FISH` (23 вида рыбы из косяков по базе Questie). `FishInfo(r)` в плане: «Поймать: … ловится: зоны» вместо «Добыть».
- Панель `CraftPlanFishFrame` (видна с удочкой в руке или по `/fish`): `CraftPlanFishSwap` (`CraftPlan.FishSwap`: `EquipItemByName`, вне боя), `CraftPlanFishLure` (защищённая, `macrotext` «/use сумка слот» + «/use 16», лучшая из `LURES`; цифра — минуты приманки из `GetWeaponEnchantInfo`), `CraftPlanFishCast` (защищённая, заклинание 7620). Атрибуты и показ — только вне боя (`pendingSecure`). Строка: навык (`GetSkillLineInfo` rank + modifier) и «поймано/сорвалось (%)» по зоне. Галочка «Громкий всплеск»: `Sound_SFXVolume=1`, музыка и фон 0, возврат при снятии удочки и на `PLAYER_LOGOUT`.
- Подсказка предмета: «Вы ловили: зона (N)…» или «Ловится в косяках рыбы». Клавиши в `Bindings.xml`. Команды `/fish`, `/fish loud`, `/fish reset`.

## 6в. Просеивание (раздел в конце кода, своя функция-обёртка)
- Журнал `CraftPlanDB.prospect.ore[руда] = { n, gems[камень] = { c = штук, t = раз } }`: на `UNIT_SPELLCAST_SENT` (Просеивание, 31252) запоминаются количества руды `ORES`, на `LOOT_OPENED` в течение 5 с после `UNIT_SPELLCAST_SUCCEEDED` — какая руда убыла на 5 и что выпало.
- Кнопка `CraftPlanProspect` (защищённая, `macrotext1` = «/cast Просеивание» + «/use сумка ячейка» стопки от 5 шт.): видна, если заклинание изучено и есть руда; цифра — сколько раз можно просеять; правый щелчок — другая руда; значок-предупреждение и строка в подсказке, если руда нужна плану (`PlanNeed`: `fullPlan` + `cont` с шагами). Стоит на полосе слева от значка карты крафта (привязана к `mapButton`, двигается вместе с полосой). Ошибка со словом «навык» в течение 2 с после щелчка — руда пропускается до роста навыка (`prospect.fail`).
- Подсказки: к руде — средний выход камней за раз; к камню — «Просеиванием: руда (t из n)».
- План («Дальше»): под недостающим камнем строка `CraftPlan.ProspectHint` — «Просеять: руда — k раз (ожидается ~x)» или «можно просеять из: руда (её нет в сумках)».

## 6г. Жилы на карте (фильтр GatherMate)
- Меняется `GatherMate.db.profile.filter["Mining"][узел]` (узлы руды — `ORE_NODES`), затем `GatherMate:SendMessage("GatherMateConfigChanged")`.
- Щелчок по руде в плане (`WhereToGetReagent` → `ToggleOre`): жилы показаны — скрыть (`db.oreOff[руда]=true`, сообщение), скрыты — показать (`false`) и перечислить зоны.
- Галочка «Скрыть жилы без пользы для навыка» (`db.hideUseless`): на вкладке «План» третьей строкой (список с -110) и на «Схеме» после радиокнопок, если «Горное дело» есть и включено (не в «Только план»): `ApplyOreFilter` скрывает жилу, если она не даёт навык горного дела (`NodeGivesSkill`: навык ≥ минимума из `GatherMate.nodeMinHarvest` и < минимум+100) и её руды нет в `UsefulItems()` — материалы не серых рецептов и (до 3 шагов) материалы для их материалов, плюс руда, чьи камни по журналу просеиваний нужны таким рецептам. Пересчёт после каждого плана (`AfterPlan`). Фильтр меняется только при смене нашего решения (`db.nodeApplied` по жилам), ручные настройки GatherMate не перебиваются. Ручной выбор щелчком важнее галочки.

## 6д. Торговец, учитель, свитки рецептов (своя функция-обёртка)
- `PlanDeficit()`: сумма материалов `fullPlan` + `cont` (рецепт и шаги) минус то, что план создаст сам, минус `TotalCount`.
- Торговец: кнопка `CraftPlanBuyButton` справа от `MerchantFrame` — покупает недостающее (`BuyMerchantItem`; пачки — по одной покупке, не более 50), только за деньги (без `extendedCost`), в пределах денег; в подсказке список и сумма. Кнопка `CraftPlanSellButton` — продать (`UseContainerItem` после подтверждения `CRAFTPLAN_SELL`) вещи для надевания — продукты ваших рецептов, качество ≤ зелёного, есть цена продажи, не сумки/боеприпасы/реликвии, не в комплектах экипировки, не материалы рецептов.
- Учитель (`hooksecurefunc("ClassTrainerFrame_Update")`, только `IsTradeskillTrainer()`): у доступных рецептов подпись «+N оранж.» или цвет (`Thresholds`/`KindAt` при текущем навыке), панель `CraftPlanTrainerPanel` справа — до 8 рецептов с наибольшим N и ценой, щелчок — `SelectTrainerService` + выделение.
- Свиток рецепта (`OnTooltipSetItem`): название после «:» ищется в `CraftPlanThresholds` — «изучен / не изучен / откройте окно профессии», цвет при текущем навыке и пороги.

## 6е. Торговцы в меню Questie
- `CraftPlan.UpdateQuestieVendors` (после каждого плана и при открытии торговца, в `pcall`): недостающее плану (`CraftPlan.PlanDeficit`) → `Townsfolk:PopulateVendors` (фракция, флаг торговца) → `Questie.db.char.vendorList["Торговцы для CraftPlan"]` (массив номеров NPC), значок `INV_Misc_Coin_02` в `QuestieMenu.private.townsfolk_texturemap`. Пункт появляется в меню Questie «Торговец»; если он включён (`townsfolkConfig`), значки перерисовываются при смене списка. Если окно торговца открывали, его реальный ассортимент (`db.vendorStock[номер NPC]`, пишет `ScanMerchant`) важнее базы Questie: торговец остаётся, только если правда продаёт недостающее. Пересчёт — только при изменении набора материалов или числа известных торговцев.
- «Торговцы рецептами для CraftPlan» (своя обёртка после раздела торговца/учителя): через 5 с после входа один раз перебирает `QuestieDB.ItemPointers` (1500 предметов за кадр), русское название «Префикс: рецепт» сверяет с `CraftPlanThresholds` (без учёта регистра и ё; «Формула чар для X: Y» → «Чары для X - Y»). `CraftPlan.UpdateRecipeVendors` (после каждого плана): рецепты профессий персонажа, которых нет в списке изученных (`db.profs[проф].recipes`, если окно открывали) → торговцы через `Townsfolk:PopulateVendors` → `vendorList["Торговцы рецептами для CraftPlan"]`, значок `INV_Scroll_03`, в подсказке к значку — до 12 рецептов. Запас ограниченных рецептов Questie не знает.
- Основной код близок к пределу Lua в 200 локальных переменных: новые части оформлять в `do … end` или функции-обёртки.

## 7. Учителя (`ShowTrainers`)
Перебирает базу NPC Questie один раз на профессию (результат кэшируется), берёт NPC с подписью «Учитель/Учительница …<профессия>» своей фракции. Отмечает на карте мира тех, кто в текущей зоне, иначе всех (до 25), в чат — до 8 имён с зонами. Предыдущие метки учителей снимаются.

### Запомненные учителя
- На `TRAINER_SHOW` у учителя профессии `RememberTrainer` (профессия — по подписи NPC из скрытой подсказки `CraftPlanScanTip`, иначе по `GetTrainerServiceSkillLine`; при неудаче — сообщение в чат) сохраняет `db.trainers[проф][номер NPC из GUID или имя] = { name, id, zone, c, z, x, y }` (координаты игрока по текущей карте; если открыта карта мира — не пишем). `ShowTrainers` дополнительно ставит метки TomTom (`AddZWaypoint`) для запомненных учителей, которых нет в списке из Questie, и пишет их в чат; `ClearTrainers` убирает и их. `CraftPlan.EnsureQuestieTrainers` (после плана и после запоминания): учитель есть в базе Questie (есть `spawns`) — его номер добавляется в `Questie.db.global.professionTrainers[номер навыка]` (меню Questie «Учитель профессии»), а если этот пункт включён — сразу `QuestieMap:ShowNPC`; нет в базе, но известна зона (`t.area` — `ZoneDB:GetAreaIdByUiMapId` по `QuestieCompat.C_Map.GetBestMapForUnit`) — запись в `QuestieDB.npcDataOverrides[номер]` (имя, точка появления, зона, фракция игрока, подпись «Учитель …», флаг учителя); Questie читает поправки раньше своей базы, живут до выхода — добавляются при каждом входе. Без зоны — постоянная метка TomTom (`t.pinned`).

## 9. Ограничения
- Рецепты видны только после открытия окна каждой профессии.
- Жёлтые/зелёные рецепты дают навык с шансом — точного числа нет по правилам игры.
- Предупреждения о порогах верны для рецептов из таблицы; для исключённых 26 и для неизвестных — цвет из последнего открытия окна.
- Почта не учитывается; банк — по последнему открытию.
- «Можно создать +N» на схеме — оценка для каждого предмета отдельно; дележ общего материала показывает только план.
- План выбирает рецепты пошагово из нескольких стратегий — хорошее, но не гарантированно идеальное распределение.
- Метки учителей по базе Questie: учитель повышает потолок, только если позволяет уровень персонажа, и не каждый учит высшим ступеням.
- Шрифт игры не знает символов «≈», «•», «×», «→» — они не используются (вместо стрелки — слова).
